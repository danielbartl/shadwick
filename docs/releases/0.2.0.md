# Shadwick 0.2.0

Released on 17 November 2026 as `dev.jbaby:shadwick:0.2.0`, from tag `v0.2.0`.

0.2.0 adds Wicket Oat's workflow components, a calendar heatmap, closer parity with Shadleaf's forms, uploads, toasts,
buttons and charts, and layout recipes. It adds to the 0.1.0 API without removing or changing a declaration; three
behaviors change, listed below. See the
[changelog](https://github.com/danielbartl/shadwick/blob/main/CHANGELOG.md) for every entry.

## What's new

- **Workflow components** from Wicket Oat, all working without JavaScript where they can:
  [wizard](https://danielbartl.github.io/shadwick/docs/components/wizard/) (a form in steps, each validated on Next),
  [filter](https://danielbartl.github.io/shadwick/docs/components/filter/) (a row of chips choosing one value),
  [master–detail](https://danielbartl.github.io/shadwick/docs/components/master-detail/) (a list beside the selected
  item's details, one pane at a time on a phone),
  [load-more list](https://danielbartl.github.io/shadwick/docs/components/load-more-list/) (a batch at a time, or as
  you scroll) and [CRUD](https://danielbartl.github.io/shadwick/docs/components/crud/) (New, Edit and Delete around a
  data table, with an edit dialog and a confirmation).
- **Calendar heatmap** (`SwCalendarHeatmap`): one cell per day in weeks and weekdays, up to three years, with a native
  table of every day and keyboard exploration.
- **Forms:** horizontal and responsive field layouts, field groups, and `SwFormErrors`, one summary of a form's errors
  that links each to its field.
- **Uploads:** `SwFileDropzone` shows files as attachments, in a list or a grid with image previews, and shows upload
  progress with a Cancel button during Ajax submits.
- **Toasts** stack as in shadcn/ui's Sonner, at a position of your choice.
- **Smaller additions:** four more button sizes with a 44-pixel touch target for small icon buttons, mixed-state
  checkboxes, empty states without an outline, icon size and stroke width, small confirmations with an icon, chart
  category grid lines and margins, and sidebar groups that all start open.
- **Docs:** six copy-ready [layout recipes](https://danielbartl.github.io/shadwick/docs/layouts/overview/), each running
  in the examples app, and a
  [Coming from shadcn/ui](https://danielbartl.github.io/shadwick/docs/guides/coming-from-shadcn/) guide.

## Changes in behavior

- **Toasts stack** by default: the newest in front, at most three showing, spreading out on hover or focus. 0.1.0
  showed every toast in a scrolling column. `ShadwickSettings.setVisibleToasts(...)` changes the count.
- **`SwFileDropzone` rows are attachments.** Applications that styled `.sw-file-upload-item`, `-name` or `-size` should
  style the attachment's parts instead.
- **A component with the wrong id** given to a factory or slot fails with one message everywhere, and `null` content
  for a dialog, popover, empty state, collapsible, sidebar or attachment slot throws `IllegalArgumentException` instead
  of `NullPointerException`.

## Fixes

- A dialog now shows errors its fields don't show in place (one reported on a field itself, or a second on the same
  input), and a session message left over from an earlier request no longer keeps it open.
- A server-search combobox no longer empties itself on form Reset, and a custom select's fallback no longer leaves the
  native select's button in the tab order; both happened when the page was enhanced before it had fully loaded.
- A link styled as a button inside a dialog, sheet, empty state, field description or accordion is no longer
  underlined.

## Coordinates and requirements

```xml
<dependency>
    <groupId>dev.jbaby</groupId>
    <artifactId>shadwick</artifactId>
    <version>0.2.0</version>
</dependency>
```

The requirements are unchanged from 0.1.0: Java 21+, Apache Wicket 11.0.0 and Jakarta Servlet 6.1+. Keep Wicket modules
aligned in the application. Maven Central receives the parent POM and the library's POM, binary, sources and Javadoc,
with signatures and checksums; the examples application is not published.

Serialization is tested within one build: drain or invalidate stored pages and sessions when moving from 0.1.0, as for
any changed build. Chromium and Firefox are the automated browser targets.
